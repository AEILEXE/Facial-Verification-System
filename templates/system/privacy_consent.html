Privacy & Data Consent Notice

How FANSC collects, secures, and uses personal and biometric data.

Back to Dashboard
1. What Personal Data Is Collected
  • Full name, date of birth, gender, address (province, municipality, barangay).
  • Contact number (optional).
  • Senior Citizen ID / OSCA number, valid government ID type and number (if presented at registration).
  • One or more face captures used to generate a FaceNet embedding (mathematical representation of the face).
  • Authorized representative information when a senior citizen cannot personally claim.
  • Verification attempts, claim records, and audit events created when staff uses the system.
2. Why Facial Data Is Collected

Facial verification ensures that only the rightful senior citizen (or their registered representative) can claim the stipend. It replaces fragile manual checks (visual ID, signature comparison) that are vulnerable to impersonation and duplicate claims.

The face is used only to confirm identity at the point of payout — it is never used for general surveillance, mass identification, or sharing with third parties.

3. How Face Data Is Stored
  • Raw webcam frames are NOT normally stored. Live verification frames are processed in memory and discarded once the FaceNet embedding has been computed.
  • What is stored is a FaceNet embedding — a list of numbers describing the geometry of the face. The original image cannot be reconstructed from this list.
  • Embeddings are encrypted at rest using Fernet (AES-128-CBC + HMAC-SHA256) with a key (EMBEDDING_ENCRYPTION_KEY) held only by the deploying barangay office.
  • Registration photos may be retained for human review of duplicate-face cases or admin re-enrollment; they are protected by the same OS-level file permissions as the database.
4. Who Can Access the Data
  • Staff — can register beneficiaries and run verifications. Cannot see other staff's attempts or the full audit log.
  • President — can approve manual reviews, release claims, and view all reports.
  • Admin — can manage users and beneficiaries, approve registrations, and view all reports and logs.
  • Technical Administrator — full technical access (system health, network/HTTPS status, audit logs, configuration).
  • No external party, government agency, or vendor has remote access. Data lives on the barangay's local network.
5. Data Retention
  • Beneficiary records are retained for as long as the person is enrolled in the senior citizen program.
  • Verification attempts and audit logs are retained for accountability and reporting (recommended minimum 2 years).
  • Deactivated or deceased beneficiaries are marked inactive, not deleted, so the audit trail of past claims remains intact.
  • Backups follow the same retention; old backups should be securely wiped when no longer needed.
6. Correction, Deactivation, and Withdrawal

A senior citizen (or their authorized representative) may at any time request:

  • Correction of personal details — staff edits the record; the change is recorded in the audit log.
  • Re-enrollment of face data if appearance has changed significantly (illness, weight change, etc.).
  • Deactivation — the beneficiary record is marked inactive and can no longer claim. A reason is required and recorded.
  • Withdrawal from the program — treated the same as deactivation. Historical claim records are kept for audit purposes; the stored face embedding is no longer used for matching.

Requests are filed at the barangay office. Sensitive changes (deactivation, face re-enrollment) require admin approval and a documented reason.

7. Questions or Concerns

For any privacy concern, please contact the barangay office where you registered. The Technical Administrator handles technical questions about how data is stored and secured.
