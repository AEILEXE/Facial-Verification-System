# FANS-C v2.2.0 Validation Checklist

Covers the full v2.2.0 theme ("Analytics, Intelligence, Notification, UX, and Workflow Improvement") — both the new/changed behavior this release adds and a regression pass over what v2.1.18 already had working. Run on a clean or staging environment. Record PASS / FAIL / UNVERIFIED per row.

---

## Authentication

- [ ] Login with correct credentials succeeds.
- [ ] Login with wrong credentials fails with a plain-language error.
- [ ] **Refresh-logout regression fix**: log in over the plain-HTTP LAN-IP fallback (no HTTPS), refresh the page — must stay logged in (previously logged the user out). Confirm in DevTools → Application → Cookies that the `sessionid` cookie is present after the refresh.
- [ ] Log in over HTTPS (via Caddy) and confirm the session cookie still shows the `Secure` flag in DevTools — the HTTPS path's cookie security must be completely unchanged by the above fix.
- [ ] Repeated failed logins (default: 8 in 10 minutes) lock out the IP and create exactly one Security Alert notification for admins — not one per failed attempt.

## Roles & Permissions

- [ ] Staff cannot see System Administration menu at all.
- [ ] Admin sees System Administration but not IT & Network items.
- [ ] IT sees everything Admin sees plus System status pages.
- [ ] Only President can approve/reject payout schedules.
- [ ] Role Permission Matrix page (now under User Management) still renders correctly.

## Notifications

- [ ] Bell badge shows the correct unread count; 0 shows no badge.
- [ ] All 7 notification categories can actually be triggered by a real action: Approval Required, Approval Reminder, Verification Review, Fraud Alert, Security Alert, Password Reset Request, System Alert.
- [ ] Approval Reminder specifically: a request left pending 48+ hours gets exactly one reminder (visit Manual Review Queue to trigger the check) — not a reminder immediately, not more than one.
- [ ] Clicking a notification navigates directly to the relevant page and marks it read.
- [ ] HIGH-priority notifications are visually distinguished (red left border in the dropdown, colored badge in the Notification Center).
- [ ] "Mark all read" clears the badge from both the dropdown and the full center page.
- [ ] A staff user never sees another user's notifications.

## Analytics

- [ ] Executive tab: stat tiles load, **plus the two new charts** (Beneficiary Growth, Monthly Distribution) render with real data.
- [ ] Operational tab: existing Verification Volume and New Registrations charts still render.
- [ ] Security tab: Fraud Risk Summary tile shows counts across **all five** signal types (not just the original three).
- [ ] All charts render via the locally-vendored Chart.js — confirm no external/CDN network request in DevTools.
- [ ] CSV export on all three tabs downloads correctly; Executive export now includes the 12-month growth/distribution data.
- [ ] Non-admin denied on all three tabs.

## Fraud / Security Review

- [ ] Security Review page (renamed from "Fraud Signals") shows **five** sections: Repeated Failures, Anomalous Staff Volume, Admin Mass-Edit Detection, Repeated Login Failures, Payout Anomalies.
- [ ] Each flagged row shows a risk badge with the explicit score, e.g. "MEDIUM (60/100)" — not just a bare LOW/MEDIUM/HIGH label.
- [ ] Manufacture a case in each of the two new sections (repeated login failures; several payout overrides/cancellations by one admin) and confirm both appear correctly banded and notify admins.
- [ ] No button anywhere on this page blocks, suspends, or denies a beneficiary, staff, or admin account — view/flag only, confirmed by reading the page, not just trusting this checklist.

## Face Verification

- [ ] Registration and verification both still work end-to-end (face capture, liveness challenge, decision).
- [ ] Confidence label next to the similarity score reads correctly for a verified / manual-review / denied result.
- [ ] Duplicate-face detection at registration still routes to the review queue, not an auto-reject.
- [ ] Re-enroll a face twice; confirm the advisory re-enrollment banner appears when a non-primary template starts winning — and confirm it never blocks the capture flow.
- [ ] Confirm (by reading `docs/FACE-VERIFICATION-INTELLIGENCE-AUDIT.md` and the actual code) that no automatic rejection based on estimated age exists anywhere in the codebase.

## Payout Approval Workflow

- [ ] Create a pending (unapproved) stipend event dated in the future. Confirm the main dashboard does **not** show it as "Next Payout" or any confirmed-sounding label — it must only appear in the separate "awaiting approval" notice, clearly marked as unconfirmed.
- [ ] Approve that event on time (before its date) — succeeds without requiring a reason.
- [ ] Create a second pending event dated in the past. Attempt to approve it — must be **rejected** unless a late-approval reason (10+ characters) is supplied.
- [ ] Supply a late-approval reason and approve — succeeds, the reason is stored on the event and appears in the audit log entry (`late_approval: true`).
- [ ] Approved future event **does** appear on the dashboard, clearly labeled "Approved."

## Reports

- [ ] Payout Claims, Distribution Summary, Staff Performance, Override & Manual Verification reports all still load and export correctly.
- [ ] "Fallback"-related labels throughout these reports now read "Manual Verification" / "Manual (ID Check)" — confirm this is **not** confused with the separate "Manual Review" (admin-approved low-confidence match) label on the same pages; the two remain visually distinct.
- [ ] The unrelated "Fallback Access (HTTP)" network-mode wording (dashboard banner, Connect Help page, System Connection page) was **not** changed — confirm it still reads correctly and wasn't accidentally renamed.

## Backup

- [ ] Manual backup (`scripts\admin\daily-backup.ps1`) still runs and produces a valid manifest.
- [ ] `verify-backup.ps1` confirms restore-readiness.
- [ ] An incomplete/failed backup still creates a System Alert notification for admins (unchanged from v2.1.18, re-confirm here).

## Restore

- [ ] `restore-backup.ps1` still restores correctly from a known-good backup *(destructive — only run against a disposable copy or with explicit approval)*.

## Administration Menu

- [ ] System Administration dropdown shows exactly 5 category headers: User Management, Verification, Distribution, Monitoring, System.
- [ ] Every link that existed before this release is still present somewhere in the reorganized menu (no functionality removed) — cross-check against the list in `accounts.tests.AdminMenuReorganizationTest`.
