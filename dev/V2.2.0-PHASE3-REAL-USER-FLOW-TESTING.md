# FANS-C v2.2.0 — Phase 3: Real User Flow Testing

This is a workflow-level pass, distinct from the section-by-section
checklist in `dev/V2.2.0-VALIDATION-CHECKLIST.md`. Each row below traces one
complete user journey and states whether it is verified by automated test
evidence (test class + method named), or whether it genuinely requires a
person at a keyboard/camera and is left **UNVERIFIED** with the specific
reason physical testing is needed.

This environment has no attached webcam and no browser session that a human
is watching, so any flow that depends on a live camera capture, real head
movement, or visual judgment of a rendered page is UNVERIFIED here by
necessity — the underlying logic for each is covered by automated tests
(cited), but a physical device pass is still required before sign-off.

## Summary

Every flow with a deterministic, code-level outcome (permissions, workflow
state machines, notification triggers, audit logging, wording) has
automated PASS evidence, most from this release's own new test classes.
The flows left UNVERIFIED all share the same root cause: they require a
physical camera and a human in front of it, or a human eyeballing rendered
CSS/layout — neither is possible from this environment. None of the
UNVERIFIED items are new risk introduced by v2.2.0; they are the same
category of manual-hardware-pass requirement every prior release
(v2.1.16's clean-VM validation, for example) has carried and explicitly
called out rather than silently assumed.

**Recommendation:** run `dev/V2.2.0-RELEASE-INSTALLATION-CHECKLIST.md`
Section 6 (clean-install smoke test with a real camera) once before wide
production rollout. This single pass covers essentially every UNVERIFIED
row above.
