# FANS-C v2.2.0 — Release Installation Checklist

Scope: building the v2.2.0 installer from a clean working tree and confirming
the produced `.exe` is internally consistent before it is handed to anyone.
This is a **build-machine** checklist — it does not cover installing onto a
target barangay server (see `V2.2.0-PRODUCTION-DEPLOYMENT-CHECKLIST.md`) or
upgrading an existing install (see
`V2.2.0-UPGRADE-CHECKLIST.md`).

---

## 1. Pre-build source state

- [ ] `git status` reviewed — every changed/new file for this release is
      accounted for (compare against the CHANGELOG `[2.2.0]` entry's file
      list, or `git diff --stat` against the last tagged release).
- [ ] No stray debug code: grep for `print(`, `pdb.set_trace`, `console.log`
      added this release (existing intentional ones excluded).
- [ ] `python manage.py check` passes with zero warnings.
- [ ] `python manage.py makemigrations --check --dry-run` passes (no
      unapplied model changes) — confirms `logs/migrations/0012_*`,
      `0013_*`, `verification/migrations/0021_*`, `0022_*` are the complete
      set for this release.
- [ ] Full test suite passes (`fans verification accounts logs
      beneficiaries`) — record the exact count in the sign-off table below.
- [ ] `python manage.py collectstatic --noinput` run fresh — confirms the
      new `templates/logs/_notification_icon.html` partial and the 2 new
      analytics chart canvases have no missing-static-file errors.

## 2. Version identity consistency

- [ ] `dev/installer/fans_c.iss`: `AppVersion=2.2.0`,
      `OutputBaseFilename=FANS-C-Setup-v2.2.0`,
      `VersionInfoVersion=2.2.0.0`, `VersionInfoProductVersion=2.2.0.0`.
- [ ] `dev/version_info.txt`: `filevers=(2, 2, 0, 0)`,
      `prodvers=(2, 2, 0, 0)`, `FileVersion`/`ProductVersion` both
      `2.2.0.0`.
- [ ] The two files agree with each other (no drift between the `.iss` and
      the PyInstaller version resource).

## 3. Packaging completeness (no spec/iss content changes expected this release)

- [ ] Confirmed via `git status --short`: this release added exactly one
      new non-migration, non-documentation file
      (`templates/logs/_notification_icon.html`), which is already covered
      by `fans_c.spec`'s blanket `templates/` datas entry — **no new
      `[Files]` entry or `hiddenimports` entry is required**.
- [ ] Double-checked: no new PowerShell scripts were added under
      `scripts/admin/` this release (the v2.1.17 packaging gap — missing
      `verify-backup.ps1`/`restore-backup.ps1` — does not recur here;
      confirm by diffing `scripts/admin/` file list against the already-8
      scripts enumerated in `dev/BUILD.md`).
- [ ] No new Django management commands were added this release (the one
      PyInstaller-risk category flagged in the original P0.2 plan) — no
      `hiddenimports` change needed.

## 4. Build

- [ ] Stop any running `fans_c.exe` before building (log file lock —
      use `taskkill /IM fans_c.exe /F`, or `wmic process where
      name='fans_c.exe' delete` if `taskkill` is denied).
- [ ] Run the PyInstaller build (`dev/build.ps1` or equivalent). First
      clean build with TensorFlow bundled: expect 15–20+ minutes.
- [ ] Confirm the `[OK] PyInstaller build succeeded` marker in the build
      log, **not just the process exit code** — `robocopy` steps inside
      the build script can leave a benign non-zero `$LASTEXITCODE` (files
      copied) that looks like failure to an external task-status check.
- [ ] Run the Inno Setup compile step; confirm
      `FANS-C-Setup-v2.2.0.exe` is produced with no compiler warnings.

## 5. Build artifact verification

- [ ] Compute and record the SHA-256 of the produced installer.
- [ ] Confirm installer file size is in the expected ~200 MB range
      (prior releases: 208.4–208.7 MB) — a large deviation signals a
      packaging problem (missing exclusion, or a missing bundle).
- [ ] Run `scripts\admin\run-smoke-tests.ps1` against a fresh install (see
      Release Installation checklist Section 6) — new URLs
      (`/analytics/executive/` new charts, notification endpoints) resolve
      inside the packaged EXE, not just under `runserver`.

## 6. Clean-install smoke test (before wide distribution)

- [ ] Install on a clean VM (no prior FANS-C install, no dev database).
- [ ] First-launch **Create Admin** screen appears; dev/build-machine
      credentials do **not** work.
- [ ] App reaches `https://fans-barangay.local` with no certificate
      warning (Caddy + mkcert root CA path).
- [ ] Login, dashboard, and at least one full verification flow succeed.
- [ ] Bell icon / notification dropdown renders without JS console errors.
- [ ] Analytics → Executive tab loads and both new charts render with the
      seed/demo data present on a fresh install (or confirm they render
      correctly empty if no verification history exists yet).
